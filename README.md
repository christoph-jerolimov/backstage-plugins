# Backstage Plugins Catalog

A community catalog of [Backstage](https://backstage.io) **plugins, packages and modules**,
expressed as [Backstage catalog entities](https://backstage.io/docs/features/software-catalog/descriptor-format/)
(`catalog-info.yaml`) — one per package, generated from over 140 public repositories.

Each entity carries:

- **Name** — the npm package name (e.g. `@backstage-community/plugin-announcements`)
- **Description** — one sentence, taken from the package's `package.json` `description`
  field when it is meaningful, or otherwise summarized from the package's README
- **Role** (`spec.type` / the `backstage-plugins.io/role` annotation) — the package's
  [`backstage.role`](https://backstage.io/docs/tooling/cli/build-system/#package-roles)
  from `package.json` (`frontend-plugin`, `backend-plugin`, `backend-plugin-module`,
  `common-library`, ...), or a best-effort inference when the field is absent
- **Repository** — the source GitHub repository
- **Stars** — the GitHub star count of that repository, where available (see below)

## Layout

```
entities/<owner>/<repo>/<entity-name>/catalog-info.yaml   # one Component entity per package
catalog-info.yaml                                          # root Location referencing every entity file
data/entities.json                                          # the same data as flat JSON (source of truth for the scripts)
data/stars-cache.json                                       # cached GitHub star counts per repository
data/plugins.csv                                             # generated CSV export (see below)
scripts/                                                      # generator scripts (see below)
```

## Scripts

All scripts are dependency-free Node.js (run with `node scripts/<name>.mjs`, Node 18+).

- **`scripts/fetch-stats.mjs`** — fetches GitHub star counts (and a few other repo
  stats) for every repository referenced by the catalog, and writes them to
  `data/stars-cache.json`. By design, it only fetches stats for a repository when
  that repository contributed **30 or fewer** cataloged plugins/packages — pass
  `--max-plugins=N` to change the cap, or `--force` to re-fetch already-cached repos.
  Set `GITHUB_TOKEN` (or `GH_TOKEN`) in the environment to raise the GitHub API rate
  limit from 60/hour to 5000/hour.
- **`scripts/generate-csv.mjs`** — reads `data/entities.json` + `data/stars-cache.json`
  and writes `data/plugins.csv` (Name, Description, Role, Repository, RepositoryUrl, Stars).
- **`scripts/update-readme.mjs`** — regenerates the markdown table below (between the
  `PLUGIN_TABLE_START` / `PLUGIN_TABLE_END` markers) from the same data.

Typical regeneration flow:

```bash
node scripts/fetch-stats.mjs      # refresh data/stars-cache.json
node scripts/generate-csv.mjs     # refresh data/plugins.csv
node scripts/update-readme.mjs    # refresh the table below
```

The `catalog-info.yaml` entity files themselves are produced by the internal
`scripts/lib/*.mjs` pipeline (clone → extract candidate packages → summarize missing
descriptions → emit YAML); that pipeline is not meant to be re-run casually since it
clones every source repository, so it isn't wired into the three scripts above.

## Notes and known gaps

- **Large monorepos** (`backstage/backstage`, `backstage/community-plugins`,
  `redhat-developer/rhdh-plugins`, `RoadieHQ/roadie-backstage-plugins`,
  `TeraSky-OSS/backstage-plugins`, `Kuadrant/kuadrant-backstage-plugin`) contribute more
  than 30 packages each, so their repository-level star counts are intentionally not
  fetched by `fetch-stats.mjs` (see above) and show blank in the table/CSV.
- A few repositories from the source list could not be cataloged:
  - `maknop/backstage-plugin-advanced-cluster-security`, `Jincoco88912/backstage-plugin-n8n`,
    `RedHatInsights/backstage-plugin-status-page` — the repository does not exist on GitHub (404).
  - `rayl15/genai-plugin-for-backstage` — repository exists but is empty (no commits).
  - `tcorp-bv/backstage-hook` — a Go project, not an npm/Backstage plugin package.
  - `tabi1412/jenkins-backstage-plugins`, `weaveworks/weaveworks-backstage-enterprise` — repository
    exists but contains no published plugin code (stub/placeholder only).
  - `dweber019/backstage-plugin-endoflife`, `dweber019/backstage-plugin-api-docs-module-wsdl` —
    each repo's README says it was moved into the `dweber019/backstage-plugins` monorepo, where
    it is already cataloged (`endoflife`, `api-docs-module-wsdl`).
- `marcus-crane/plugin-cicd-statistics-travisci` is cataloged, but its own README explicitly
  states "this is NOT a valid plugin" — a reference/demo implementation, not an installable package.
- `K-Phoen/backstage-plugin-announcements` is cataloged, but has been superseded by
  `@backstage-community/plugin-announcements` in `backstage/community-plugins`.
- `veecode-platform/spacelift-backstage-plugins` is cataloged; its relationship to any upstream
  Spacelift/Backstage plugin implementation could not be confirmed.
